# V1.0.18 本地测试说明

V1.0.17 已完成 GitHub Release 和 ZIP 发布。V1.0.18 使用 Git 标签 `v1.0.18` 标识本地测试版本，提供对应 ZIP 测试包。远程发布与后台接口部署单独进行，当前均未执行。

## 已实现

1. 设置中展示研究台授权账号的姓名和邮箱。账号资料由后台按已验证的账号 ID 查询；在线后台尚未部署相应接口时，显示已连接账号 ID。
2. 停止后保留本轮统计、运行时长和结果。最近记录跨轮次保存，侧栏显示 5 条，完整页面保留滚动 24 小时的数据，每页 50 条，可按平台来源、轮次、结果和关键词筛选。开始新一轮仅重置本轮统计，升级时保留并迁入已有记录。
每条记录新增 `sourcePlatform`，包括抖音、快手、飞瓜、星图及来源未确认。旧版本有效历史迁入新库，原始样本同步记录来源，上传放在 `rpa_feedback.source_platform`。

3. 开发调试增加本地原始采样。默认关闭，启用后自动采集运行中的卡片；也可手动采样并标记视频、直播、图文或广告。样本支持导出 JSON 和清空，最多保留 200 条 / 25 MiB，超过上限替换最早样本。

4. “继续本轮”自动恢复原推荐页；原任务页跳到精选、其他网站或已关闭时，在当前窗口找到或打开推荐页继续。沿用本轮 ID、计数、记录及剩余时长，暂停时间不计入目标；恢复失败在运行卡片下方显示原因。

## 如何测试

在 Chrome 扩展管理中加载或重新加载本项目 `dist` 目录，并刷新抖音页面使内容脚本更新。

- 暂停后在其他网站或抖音精选页点击“继续本轮”；再测试原任务页跳转或关闭后继续，确认轮次、计数与累计时长保留，并继续处理卡片。
- 开始一轮，积累记录后停止：统计与时长应保留，标题显示“本轮已结束”。
- 打开“查看近 24 小时记录”：核对总数、分页和平台来源列；来源按实际采集上下文记录，当前采集入口仍是抖音。
- 开始新一轮：本轮统计从零开始，旧的最近记录仍在，随着新记录逐条更新；完整记录页面可以选择旧轮次。
- 关闭侧栏、刷新侧栏或重启浏览器：历史记录继续存在。
- 打开设置，查看已连接研究台账号。真实姓名和邮箱需等本地后台接口部署到测试环境后再验收；当前线上旧接口继续显示账号 ID。
- 在抖音推荐页打开“设置 → 开发调试 → 保存推荐流原始采样”，人工确认当前内容类型并点击“采样当前卡片”，或启用后运行任务自动采样。
- 点击“刷新”查看采样数量，再导出 JSON。比较 `parsed.contentType`、`parsed.typeEvidence`、`attributes`、`dom` 与 `structured.candidates[].data`。
- 收集真实视频、直播、图文、广告样本后对照字段。`structured.reason` 会说明结构化数据是否取得；DOM 无权威类型字段时不能据此推断平台枚举。
- 导出完成后可关闭采样并清空样本，正常找号与上传继续独立运行。

## 数据位置与边界

设置、连接账号、统计、本轮状态使用 `chrome.storage.local`；最近记录使用扩展 IndexedDB `dra-decision-history`，采样使用扩展自身的 IndexedDB `dra-local-raw-samples`。数据属于当前 Chrome 配置，卸载或清除扩展存储会删除。

采样保留当前卡片 DOM（上限 250,000 字符）和可读取的卡片 React props 中匹配内容 ID 的结构化候选。移除脚本、表单值、敏感属性与凭据字段，并限制遍历深度和容量。样本只存本机，不进入研究台上传队列。此次未加入网络响应抓取；页面不暴露结构化数据时仍可保存 DOM。测试样本中的数值仅用于验证保存链路，不定义抖音线上类型规则。

## 后台代码

父仓库中修改了 `supabase/functions/ingest/index.ts`、`supabase/functions/pair-poll/index.ts`，新增共享 `account-profile.ts` 及测试。已有连接通过连接检查获取资料，新连接通过配对响应获取资料。没有修改数据库结构或线上配置。
