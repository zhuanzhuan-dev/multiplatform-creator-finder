## 商店详情

名称：多平台自动找号助手

简短说明：从多平台内容流中自动发现符合规则的达人和视频，并将观察结果上传到研究台。

语言：简体中文。分类：以后台当前可选项中的工作效率类别为准。

详细说明：

多平台自动找号助手用于团队达人研究：在抖音推荐流、快手推荐流和飞瓜视频库中，按配置的规则整理达人与视频观察，并在连接研究台后同步研究结果。

- 在侧边栏设置内容分类、关键词、粉丝和互动指标等筛选条件。
- 分平台启动、暂停、继续和停止任务，查看采集进度与判断原因。
- 通过网页悬浮入口打开侧栏、查看平台任务状态；支持按网站隐藏或全局关闭入口。
- 在抖音任务中配置定时运行、停留时间及互动选项。任务会依据启用的选项执行页面操作，请在启动前核对规则。
- 保存本地观察与待上传队列，支持导出本地完整观察；调试采样支持单独导出和清空。
- 连接研究台后，上传任务涉及的达人资料、视频信息、页面链接、筛选判断、互动结果和运行统计。抖音、快手的上传观察包含未命中规则的记录；飞瓜上传由独立开关控制。

使用条件：Chrome 120 或更高版本；登录相应内容平台；同步到团队研究台时需要团队授权及相应网络访问条件。各平台功能以侧栏中实际提供的选项为准。

本地测试模式使新任务结果保存在本机，已有正式上传队列仍会继续同步。安装商店版本后，Chrome 在更新服务可访问时自动获取已发布版本。

## 隐私表单

单一用途：帮助团队在支持的内容平台上按规则发现和整理达人与视频，并将采集观察同步到已授权的研究台，完成达人研究。

| 权限 | 用途说明 |
| --- | --- |
| alarms | 调度抖音定时任务、上传重试及任务维护。 |
| debugger | 在任务绑定的标签页中执行页面输入与滚动，并保持任务页面活跃，以支持后台采集。用户可在侧栏暂停或停止任务。 |
| power | 用户启用保持唤醒选项后，在运行任务期间防止系统休眠。 |
| sidePanel | 显示任务控制、筛选规则、观察结果、授权状态与设置。 |
| storage | 保存规则、偏好、任务进度、设备配对授权及待上传状态。 |
| unlimitedStorage | 保存持续采集产生的本地观察、判断历史、去重记录与上传队列，降低默认存储配额导致数据写入失败的风险。 |
| tabs | 识别和绑定支持平台的任务页面，恢复任务、定位侧栏，并管理采集所需页面。 |
| scripting | 安装或更新后，将包内悬浮入口脚本注入已经打开的普通网页。 |
| http://*/*、https://*/* | 在普通网页显示跨页面任务入口，并支持按当前网站保存隐藏偏好；在支持的平台页面采集任务所需内容，连接研究台服务。通用悬浮脚本负责入口与任务状态显示，平台采集脚本按各自匹配域运行。 |

远程代码：当前构建把可执行 JavaScript 与 React 依赖打包到扩展内部。网络返回的业务数据和图片按数据处理；提交前复核最终 ZIP 的执行路径。

数据类别填写依据：

- 网站内容：视频文案、达人资料、头像与封面链接，以及用户启用的调试采样。
- 网络浏览活动：任务涉及的页面 URL、浏览切换、停留时间、互动和采集时间。
- 用户活动：任务控制、规则判断、互动结果及运行统计。
- 身份验证信息：研究台设备配对凭据和访问令牌，用于已授权的同步请求。
- 个人身份信息：达人名称、个人主页及公开资料，以及与授权关联的设备标识。根据后台定义保守勾选相关类别。

隐私政策公开 URL、联系渠道和数据使用承诺应由发布者确认后填写；以《隐私政策草稿.md》及实际服务端处理为依据。审核声明应逐项核对后提交。

## 审核测试说明

1. 安装扩展并点击工具栏图标打开侧栏，检查任务设置和悬浮入口。
2. 在设置的开发调试区启用本地测试模式，使用审核人员自己的内容平台账号，在支持的平台页面开始一个短任务，观察采集、暂停和停止。
3. 飞瓜需要有视频库访问权限的平台账号。侧栏中的平台规则和开关分别控制任务。
4. 云端同步依赖公司研究台授权与公司网络。发布者需提供可供审核使用的受限测试路径、测试账号或后台接受的功能演示材料；在该路径可用前，保留为待提交状态。
5. 截图使用当前版本的真实界面，采用示例数据时明确标注。上传前检查图中个人信息与授权凭据。

## 首次上架与后续更新

1. 使用 Node.js 22、pnpm 10 运行 `pnpm package`；产物为 `release/multiplatform-creator-discovery-v<版本>.zip`。
2. 在开发者后台创建商店条目并上传 ZIP。将真实商店 ID 和安装 URL 记录到本文件。
3. 填写详情、截图、隐私政策、权限用途与审核说明，选择 Unlisted，按目标员工所在地设置地区。
4. 审核通过并发布后，用普通浏览器配置验证安装、连接研究台和采集上传，再把固定商店 URL 发给同事。
5. 更新时递增版本号、生成对应版本说明、运行 `pnpm package`，上传到同一个商店条目并提交发布。保持同一条目以维持扩展 ID 与用户更新关系。
6. 以后台已发布版本和客户端实际版本确认更新结果。Chrome 下载更新后可能等待扩展空闲或浏览器重启再安装；避免为加速更新而强制中断采集。

商店管理自动更新，无需为商店产物增加自托管 `update_url` 或另行维护更新下载器。

## ZIP 用户迁移

1. 停止各平台任务，关闭旧版定时运行，等待正式上传队列处理完成；导出本地完整观察，另行记录自定义规则和设置。
2. 停用旧版扩展并保留旧目录和导出文件，以便核对；通过商店链接安装新版。
3. 新版重新连接研究台，恢复需要的规则，刷新内容平台网页，执行短任务验证。
4. 核对云端数据和新版状态后再移除旧版。移除扩展会清除其本地存储。

本地加载 ID 与商店 ID 可能不同。当前完整观察导出用于备份，当前版本未提供对应的一键导入或跨 ID 自动迁移功能。
