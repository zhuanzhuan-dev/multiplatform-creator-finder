# 运行规则：平台隔离、持久化与词命中

对应插件侧栏「任务设置 → 视频与账号规则」。字段默认值和操作步骤见 [使用说明手册 · 筛选规则配置](./使用说明手册.md#筛选规则配置)。交互口径见 [产品交互与统计口径](./产品交互与统计口径.md)。

本文只回答两件事：改一个平台会不会动到别的平台；正负向词怎么命中、准召靠什么。

## 结论

- **想找的内容、排除词、时长 / 点赞 / 播放 / 粉丝门槛按任务独立保存。** 改快手不会改抖音；改 B 站综合热门不会改 B 站首页推荐。
- **关闭侧栏、重启 Chrome 不会回到默认。** 有效配置写在本机 `chrome.storage.local`。看起来像被重置，多半是规则改了但没点「保存规则」。
- **词命中是规范化后的子串包含，不是语义理解。** 排除词优先；正向一个都没命中时，硬门槛过了仍留下，标「需人工确认」。采集循环目前只跑本地规则引擎。

## 各平台存哪里

```
本机 chrome.storage.local
+-------------------+  +--------------------+  +---------------------------+
| 抖音              |  | 快手               |  | B站首页 / B站热门         |
| draSettings       |  | draKuaishouConfig  |  | draBilibiliConfig         |
| draRules          |  |   settings + rules |  | draBilibiliPopularConfig  |
| draSettingsDraft  |  |                    |  |                           |
+-------------------+  +--------------------+  +---------------------------+
+-------------------+  +--------------------+
| 飞瓜规避词        |  | 星图规避词 / 页数  |
| 跟抖音表单隔离    |  | draXingtuConfig    |
+-------------------+  +--------------------+

共用、不跟规则走：研究台配对、主题、悬浮入口、今日已刷汇总、上传队列
```

| 任务 | 存储 | 规则形态 |
|---|---|---|
| 抖音推荐流 | `draSettings` / `draRules` / `draSettingsDraft` | 时长、点赞、粉丝 + 正向类目 + 排除关键词 |
| 快手推荐流 | `draKuaishouConfig` | 与抖音同一套规则形态，各自一份 |
| B 站首页推荐 | `draBilibiliConfig` | 播放量门槛 + 分区 / 标题黑名单 + 正向类目 |
| B 站综合热门 | `draBilibiliPopularConfig` | 与首页同一套形态，各自一份 |
| 飞瓜视频库 | 抖音规则对象里的 `feiguaKeywords`（抖音表单保存时不会覆盖） | 整账号规避词 |
| 星图达人广场 | `draXingtuConfig` | 整账号规避词、批次页数、翻页间隔 |

保存请求带平台标识。切换任务时侧栏换回该任务自己的表单；过期响应不会盖到当前页。某一边在跑时，只锁**当前任务**，另一边仍可改下轮设置。

快手本机第一次出现、还没有自己的配置时，会从当时的抖音配置复制一份，之后分开。B 站热门从旧的共用 B 站配置迁出后，两路也分开。

这些能力只在部分任务生效，不随规则复制：

- **正向互动**（点赞 / 收藏 / 关注）只执行在抖音
- **定时启动**只读抖音 `draSettings.schedule`
- 研究台连接、主题、今日已刷、上传队列全插件共用

## 打开会不会重置

不会。有效配置在本机扩展存储里，关侧栏、重启浏览器后按任务读回。

两套保存节奏：

| 区域 | 怎么落盘 | 没保存就关掉 |
|---|---|---|
| 运行设置（停留、条数 / 时长目标、本地测试） | 改完自动存 | 读回上次已保存值 |
| 视频与账号规则（想找的内容、排除词、门槛） | 必须点「保存规则」 | 读回上次已保存值，未保存的编辑丢掉 |

校验失败时，不合法内容进草稿，提示「已恢复未完成的草稿」。任务继续用上一份有效配置，草稿修正并保存后才换新。

同一侧栏会话里切换平台，未保存的表单会先放进内存缓存；关掉侧栏后缓存清空，只剩已落盘的配置。

这些情况才会真的回到默认或丢设置：

- 卸载扩展，或清除该扩展的网站数据
- 点了「应用默认预设」/「应用随机预设」
- 换了一台电脑或另一个 Chrome 配置（不同步）

改规则只影响**下一轮**。运行中的任务继续用开始时固定下来的那份。要让新规则生效：停本轮，再开新一轮。已处理过的内容不会重判。

## 正负向词怎么命中

本地引擎做文字包含，不理解画面或同义说法。

```
标题 + 昵称 + 话题（这些有字，就不用卡片上的按钮 / 弹幕）
        |
        v
  NFKC 规范化 + 小写 + 空白收成一格
        |
        +-- 排除词命中任意一条 --> 直接淘汰（负向优先）
        |
        +-- 时长 / 点赞或播放等硬门槛不过 --> 淘汰
        |
        +-- 正向类目关键词命中 --> 记类型、加分
        |
        +-- 正向一个都没命中 --> 仍收下，标「需人工确认」
```

实现落在 `lib/rule-engine.js`（抖音 / 快手）和 `lib/bilibili-rules.js`（B 站）。匹配函数是规范化后的 `includes`。

**匹配范围**

- 优先用结构化字段：视频描述、作者昵称、话题
- 这些字段都空时，才退回卡片全文
- 有标题时，弹幕或按钮里的「探店」不会单独造成正向或负向命中
- 达人主页再扫一遍昵称、简介、已加载作品文字；排除词在主页命中同样整号剔除

**负向（排除关键词）**

- 界面名是「排除关键词」，持久化字段仍是 `gameBlacklist`
- 适用于所有内容类别，不限于游戏
- 任一排除词被包含即淘汰，即使同时也命中正向类目
- B 站另有分区名黑名单、标题关键词黑名单、OGV / 影视内容；数码类默认不纳入
- 飞瓜、星图是整账号规避词：当前页或后续页命中，本轮去掉该账号全部候选

**正向（想找的内容）**

- 每个启用类目有自己的关键词和加分
- 一类目命中至少一个词即记该类目
- 可同时命中多个类目，评分取最高分类目加分
- 至少保留一个启用类目才能保存

**硬门槛与词无关**：时长、点赞（抖音 / 快手）、播放量（B 站）、粉丝上下限、低粉新号例外。直播、图文、广告、类型未确认不进这套词匹配，直接按类型跳过。

## 准召怎么保

词表本身没有统计意义上的精确率 / 召回率承诺。现网靠分层兜底：

| 层 | 作用 | 对准召的影响 |
|---|---|---|
| 排除词 | 一命中就杀 | 词短、太泛会误杀，伤召回 |
| 硬门槛 | 时长、点赞 / 播放、粉丝 | 确定，和词无关 |
| 正向词 | 给类型、加分、抖音正向互动资格 | 词太宽误收，伤精度；同义说法没写进表会漏 |
| 词没命中仍保留 | 标「需人工确认」 | 保召回，精度靠人看 |

因此：

- 排除词写具体、写长（「和平精英」而不是「精英」）
- 正向少用单字和生活口语；每个类目用业务里标题 / 话题真会出现的 3–6 个说法
- 「日常」「旅行」「校园」「剧情」这类默认词容易过宽
- 单独写 `ai` 会撞进很多英文词；默认 AI 类用「ai漫剧」「aigc」这类更长片语
- 漏检应进「需人工确认」，不要靠把负向加得很宽来少看几条
- 只有明确命中正向类目的抖音视频才进入点赞 / 收藏 / 关注配额；需人工确认的不互动

研究台已提供 `/api/functions/v1/agent`：`evaluate` 在硬门槛过、关键词未中时按类目名做语义判断（置信度低于 0.6 丢掉）；`suggest_rules` 按意图生成类目和排除词草稿。插件里已有调用客户端，**采集循环还没接上**。线上仍是「词没中 → 人工确认」，不是「词没中 → 模型再判一次」。
