# 插件桌面尺寸与缩放验收

关联：[FAI-806](https://linear.app/fxxkai/issue/FAI-806)。版本 1.1.28，本次提交交付界面适配修复与验收记录；尚未打包或发布。

## 范围与目标

用户在 Windows 电脑看到 B 站规则的发布天数框被挤窄，播放量也显示不完整。本次检查插件六个平台入口、全部侧栏表单、共享控件、弹层、近 24 小时记录页与更新页。沿用现有主题与规则语义，按容器可用宽度重排，让数值、单位、说明、错误提示和操作保持可用。

依据 Product Design 的响应式/键盘/错误恢复审查方法，以及 ui-ux-pro-max 的 Web 溢出处理和 React 受控表单规则。检查的是桌面浏览器有效 CSS 宽度；显示器物理分辨率、系统缩放、浏览器缩放和侧栏拖动都会影响该宽度。

## 已有基础

现有页面使用相同主题 token、受控输入、焦点样式和折叠设置；运行与规则分开。多数普通网格已支持自动换行。保留这些基础，修复局部固定列与最小尺寸问题。

## 发现与修正

| 组件 | 问题与依据 | 修正 |
| --- | --- | --- |
| B 站首页/热门播放与发布规则 | 360px 下实测播放输入 59.4px、天数输入 27px；两组条件和删除键硬塞同一行 | 条件组按容器宽度自动换行；极窄容器删除键独占一行；同宽修复后分别约 176px、160px |
| 飞瓜/停留时间三列表单 | `repeat(3, minmax(0, 1fr))` 允许三个数字框无限变窄 | 按每个字段的可用宽度自动排为一至三列 |
| 数字输入错误提示 | NumberInput 原来返回输入和提示两个同级节点，嵌套网格会把提示当成额外单元格，挤占“天”单位 | 输入与提示组成一个字段，保持原有 aria-invalid/aria-describedby 与校验语义 |
| 长关键词 | 连续英文无法断行，标签内部删除键可能被挤压 | 文本可断行，删除键保持尺寸；键入、回车添加、删除已实测 |
| 时间、百分比、复选框与说明 | 时间行列宽预算偏小；百分比与标题同行；原生复选框可能参与压缩 | 增加时间行宽度预算，百分比与标题可换行，复选框/单选框保持尺寸；说明与错误长文本断行 |
| 设置及平台菜单 | 240×480 时设置弹层底部实测 526.8px，超出窗口 | 预留顶部空间并限制菜单高度，内容内部滚动；修复后底部 462.8px |
| 星图指标详情 | 固定三列在嵌套卡片中压缩指标 | 指标按容器宽度自动换列，候选详情展开后多宽度实测 |
| 记录页 | 统计名称可能省略；窄卡片保留视频最小宽度和固定列位置 | 汇总可换行；小于等于 480px 时按单列呈现；保留桌面表格区域内横向滚动 |
| 更新页 | 图标、版本标题和底部按钮固定并排，窄窗口有挤压风险 | 标题与页脚按宽度换行，说明列可收缩，长文本可断行 |

## 实测矩阵与操作

- macOS Chrome，使用生产构建的页面，Chrome API 由本地 `scripts/preview-extension.mjs` 提供确定性测试数据。未启动采集、连接外部服务或写入真实达人数据。
- 侧栏：240、280、320、360、400、480、640、800 CSS px，常规高度 900px；设置额外检查 240×480 与 320×600。
- 记录页：240、320、480、720、721、1024、1280、1920px；更新页：240、320、480、720、1024、1280、1920px。
- Chrome 原生缩放菜单实测 125%、150%、175%、200%；实际有效宽度分别约 866、722、619、541px，Retina DPR 随之为 2.5、3、3.5、4。200% 时再次编辑天数成功。完成后恢复 100% 和默认视口。
- B 站输入十位播放量 `1234567890`、三位天数 `365`；清空数字显示错误；Tab 从发布天数进入对应删除按钮。
- 飞瓜输入小数间隔 `3.5` / `6.5`；抖音展开评分规则，清空最低均赞、输入越界百分比显示提示；关键词完成添加和删除。
- 设置切换浅/深色（实际测试为系统主题与深色），调试下拉选择直播；Escape 关闭菜单并返回触发按钮。主题已恢复系统。
- 最终页面容器边界检查未见非预期横向溢出或按钮/错误文本截断。桌面表格的区域内横向滚动保留。浏览器其他扩展注入内容不纳入本插件页面宽度判定。
