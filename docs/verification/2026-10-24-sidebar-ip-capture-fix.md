# 侧栏 IP 漏采与紧凑展示修复

关联：[FAI-816](https://linear.app/fxxkai/issue/FAI-816)。用户实机为 V1.1.29，明确要求完整主页补采关闭时继续复用侧栏响应，并保持版本号 1.1.29。原有队列模型与 OpenSpec 草稿保留。

## 真实原因与复现

2026-10-24 在独立 Chrome 推荐标签页打开普通侧栏并选择「TA的作品」，通过原生 DevTools Network / Preview 核对当前实际请求：

- `GET https://www-hj.douyin.com/aweme/v1/web/user/profile/other/`，XHR，HTTP 200。
- 响应 `status_code=0`，`user.nickname=凡夫说史`，`user.ip_location=IP属地：北京`；响应 `sec_uid` 与侧栏账号一致。
- 原实现仅接受 `https://www.douyin.com`，这个实际请求在进入 IP 解码前就被排除。该证据说明本机当前请求未被接收，不能归因为平台未提供 IP 或关闭主页补采。
- 另有独立时序缺陷：采集脚本只在停留前读取响应，停留期间到达的数据未合入提交。两项回归用例在修复前分别失败，输出为请求身份 `null`、最终 IP `undefined`。

原始请求头、Cookie、查询参数及完整用户响应未保存。仅保留必要字段摘录于外层 `outputs/ip-sidebar-fix-20261024/native-sidebar-response.json`。诊断标签页已关闭，DevTools 过滤条件恢复原值；主页补采设置保持关闭。

## 修改

- 资料捕获接受已核实的两个 HTTPS 域名和同一资料路径；继续按 GET、请求账号与响应账号匹配，保留稳定达人身份。仅观察网站自己的 fetch/XHR，不新增资料请求。
- 提交前再读取已到达的侧栏缓存，保存停留期间返回的 IP；快速淘汰记录也可复用已有同账号响应，保持不额外读取主页资料和不开页。
- 最近记录将平台与 IP 合并为同一行，例如「抖音 · IP 北京」。未取得、平台未提供和读取失败分别显示并提供解释。其他平台没有 IP 事实时不追加空 IP 标签；本机历史同步使用紧凑展示。
- 按用户要求保持 manifest、package、构建产物版本均为 1.1.29；在现有 1.1.29 更新说明中整合本次修复。
