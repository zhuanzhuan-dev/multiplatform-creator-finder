# V1.0.26 抖音与飞瓜并行

## 当前交付范围

抖音推荐流和飞瓜视频库各维护一个独立任务和独立业务页面，可以同时采集。顶部账号连接、通用设置和平台任务切换共用。飞瓜当前设置为仅本地采集，历史飞瓜待上传记录保留并暂停发送，抖音上传保持独立。快手仍处于页面识别阶段，采集器尚未接入；需要确认快手具体网址及推荐流或搜索列表后继续实现。

当前飞瓜自动翻页入口为 `https://dy.feigua.cn/app/#/video/library/all`。旧飞瓜插件的注入范围为整个 `https://dy.feigua.cn/app/*`，按页面内容识别视频行；目前自动运行范围仍比旧插件窄，其他飞瓜列表需要独立核对分页与列表结构。

## 使用方法

1. 在 Chrome 扩展管理页重新加载 `dist/`，确认 V1.0.26；刷新要采集的抖音和飞瓜网页。
2. 在抖音推荐页打开侧栏，“查看与控制任务”选择“跟随当前标签页”，点击“开始本轮”。
3. 切换飞瓜视频库，设置好网页筛选条件，再打开侧栏并点击“开始采集”。
4. 侧栏顶部同时显示两路任务的状态和已刷数量。切换标签页仅改变跟随查看的平台。
5. 通过任务选择框手动查看抖音或飞瓜，暂停、继续和停止只作用于当前查看的平台。飞瓜独立页面提供“继续采集”“结束并保存”“打开飞瓜视频库”，并显示已采集页、视频条数、候选账号、排除账号与重复跳过数量。手动选择飞瓜后开始新任务会打开飞瓜视频库。
6. 飞瓜暂停后点击“继续采集”：优先恢复原飞瓜标签页；原页不可用时，在指定窗口复用或新建视频库标签页。保留本轮计数、候选和去重记录，重新经过旧页面时跳过重复内容。网页重新打开后应核对飞瓜筛选条件。关闭飞瓜标签页仅暂停飞瓜，抖音继续运行。

## 任务与队列规则

- 抖音、飞瓜分别保存任务 ID、循环 ID、绑定标签页、计数、运行时长、暂停与停止状态。
- 飞瓜开始时保存配置快照，运行中的规避词、测试模式与任务目标不随另一平台的配置调整而变化。抖音运行期间，抖音配置保持锁定；飞瓜的下轮数量目标与规避词在独立页面保存，抖音继续运行。飞瓜暂停任务继续使用原目标和规则，新一轮使用最新设置。
- 飞瓜保留跨页整账号排除规则，完整观察在筛选之前持久化，排除只影响候选。当前上传关闭；以后启用发送时，新观察经过门禁进入共享队列，候选汇总与观察发送分开。旧候选处理路径保留迁移能力。
- 两个平台共用账号连接、上传队列、批量发送和失败重试。按采集时间优先串行发送，每批只合并排序后连续属于同一任务的记录；失败记录退避期间允许后续正常记录发送。上传成功和拒绝数归属于对应任务。
- 新采集的本地测试记录保持本地状态；已在队列中的正式记录继续独立同步。断开研究台连接会暂停正式采集任务，并保留队列。
- 队列达到容量时保留未上传数据并继续排空队列。独立观察存储达到上限时暂停采集并提示；完整原始观察支持 JSON 导出。
- 飞瓜浏览采集默认开启，自动任务暂停或结束后仍可读取用户打开的已适配页面。进入飞瓜详情页会暂停正在运行的飞瓜任务；回到列表后由用户点击继续。
- 等待、巡检和停止闹钟独立。暂停一个平台不会释放另一个运行平台所需的系统唤醒请求。
- 旧版本单任务为飞瓜时，迁移到独立飞瓜状态；历史队列和候选继续保留。旧版抖音状态保持原存储位置。

## 自动化检查

`pnpm check` 包含类型检查、测试、构建和 dist 校验。新增集成检查覆盖：

- 抖音运行中启动飞瓜，两路分别采集并进入同一队列。
- 平台状态选择、暂停隔离、等待取消、关闭飞瓜标签页后抖音继续。
- 上传单次执行、采集时间排序、连续任务批次、失败退避隔离、成功结果按任务计数。
- 共享队列容量保护、飞瓜候选重试、正式队列与新任务测试模式隔离。
- 飞瓜启动中取消，旧请求不再启动循环。
- 飞瓜继续时自动恢复视频库、原标签页关闭后新建页面、计数保留与旧页面重放去重。
- 抖音运行时独立保存飞瓜下轮设置，不修改抖音目标。
- 旧版飞瓜任务迁移及工作进程重启后的候选保留。

## 真实浏览器验收

自动化使用隔离存储和模拟浏览器接口；网页预览用于检查任务选择和状态展示。真实 Chrome 双平台后台连续采集与线上入库需要分别验收，不能用模拟测试替代。

2026-09-10 已完成飞瓜恢复实测：重新加载本地扩展并刷新飞瓜页面后，18 页、357 条及原候选记录保留；点击“继续采集”自动将原飞瓜标签页恢复到视频库，自动采集并翻页至第 5 页，最终手动暂停在 371/1000 条。过程中观察到重复跳过数增加、原候选继续显示，抖音始终保持已暂停 1000 条。界面显示“仅本地保存”。此次未执行结束汇总、双平台同时运行或线上入库验收。

覆盖同版本 dist 后必须在扩展管理页点击“重新加载”，再刷新采集网页。仅重新打开侧栏会出现界面已更新、后台仍运行旧逻辑的状态；本次重新加载前可复现旧的原标签页错误，重新加载后恢复成功。

先用本地测试模式：让两路各处理数条，切换标签页并分别暂停，确认另一平台计数继续增加；然后分别检查页面停滞、关闭标签页、暂停恢复和结束汇总。正式上传验收时，再检查两路记录均携带正确来源和任务 ID，并在研究台确认实际入库。

本次代码与 dist 用于本地验收，保持未提交。当前架构与最新验收结果见 [架构规范](./多平台采集架构-spec.md) 和 [验收记录](./多平台采集架构-验收.md)；上面的 371/1000 条属于此前版本的历史实测，当前自动任务目标使用页面批次。
